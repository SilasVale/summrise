# The Runs Page — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An operator runs a command on a device and reads its exit, output and history, from the console.

**Architecture:** One console page in the rail (after Monitors, before Audit) over the existing three tools (`runs.exec`, `runs.list`, `runs.get`), through the same grant path as every other pane. No device or console route changes.

**Tech Stack:** React 19 + TypeScript, `callTool(grant, name, args)`, the console's existing styles.

**Spec:** this plan; the device side is `device/device/src/capabilities/runs.rs` and the schemas in `device/device/src/mcp.rs`.

## The shapes (verified in the code, not guessed)

- `runs.exec {command, args?, cwd?, timeout_ms?, env?, shell?}` → `{id, exit_code?, timed_out, duration_ms, stdout, stderr, truncated, history_recorded}`. It **blocks** for the run's duration (default 60 s, max 10 min).
- `runs.list {limit?}` → newest first, `[{id, command, args, cwd, exit_code?, timed_out, duration_ms, started_at_ms, stdout_bytes, stderr_bytes}]`.
- `runs.get {id}` → one `Record`: the same metadata, **no output bodies** (history keeps their sizes only). The page must say so rather than showing an empty output box.
- `runs.exec` is destructive and audited; a grant without it is refused with the device's sentence.

## Global Constraints

- Only console web files change (+ the committed `dist/index.html`); no dependencies; no Rust.
- Every device call is `callTool(grant, …)`.
- The three states as Memory/Monitors: no device, no grant, view.
- English UI and comments.
- Gates: `tsc --noEmit` zero errors; `build-web.sh` succeeds and `--check` is current; bundle committed.

## Review Focus

1. A long run does not look frozen: the button shows the run is in flight, and the form is not resubmittable.
2. The result shows exit code (or `timed out`), duration, stdout, stderr, and says when the output was cut (`truncated`).
3. History rows show what history actually has (exit, duration, sizes) and clicking one fetches `runs.get`; the detail says the bodies are not retained rather than showing an empty pre.
4. `shell` and argv modes are distinguishable; env is not offered unless it is implemented correctly (omit it — the device caps it at 32 entries).
5. A refusal (empty command, over-cap) is the device's sentence.
