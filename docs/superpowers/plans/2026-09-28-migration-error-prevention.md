# 迁移防错计划 — 从**真的发生过的错**长出来

> 每一个错误模式都带**证据**（今晚实测，或 [secureyeoman 的 TS→Rust 复盘](https://raw.githubusercontent.com/MacCracken/secureyeoman/refs/heads/main/docs/development/migration-finds.md)）、**防法**、以及**怎么验证防法真的生效**。
> 判据是这一条：**防法本身也要能被证伪**——不然它只是又一句听起来对的话。

---

## 错误模式 1：迁移中**静默丢掉东西**（最贵的一个）

**证据**：secureyeoman 9 天迁了 944 条路由 / 54K 行，编译干净、核心域有真逻辑——**而中间件安全栈 16 层只搬了 5 层**（限流 / RBAC / 请求体限制 / IP 信誉 / 请求指纹 / 背压 / 所有权守卫 / 本地网络检查 / CORS 限制 / IPv6 规范化 / multipart 全缺）、**59 个端点没有 handler**（功能"silently broken"）、**Rust 侧零集成测试**。它的 `server.rs` 里甚至写着 `Stubs for Phase 7.1: …`——**acknowledged but never built**。

**防法**：
1. **迁移前先出清单**，逐项列出"现在有什么"。对门禁是 `ls scripts/test/` 的 68 个；对 Worker 是它的路由表；对 UI 是它的组件与导出。
2. **搬一个划掉一个**，而**"没搬"必须显式列出**——不是留白。
3. **每次提交的信息里带三行**：`已搬 / 已删 / 待办`。

**怎么验证防法生效**：迁移结束时，**清单上每一项的状态都是显式的**（搬了 / 删了 / 留着并写了为什么）。**只要有一项没有状态，防法就没生效。**

## 错误模式 2：等价没被证明就删旧的

**证据**：那份复盘的 TS 代码 **1,726 个文件一个都没删**——**而那是它还能被修的唯一原因**。反过来说：**删了就没法修**。

**防法**：**旧的在新版被证明等价之前不删。** 而"证明"不是"我看着像"——是：
- **同一份输入喂给两个版本，断言结论一致**（判决 **与消息文本**）
- **含失败用例与边界用例**（只有 happy path 的等价证明等于没证明）
- **再加一个"不该咬"的用例**（今晚那个：围栏内的 `###` 必须两版都过）

**怎么验证防法生效**：**能说出一个两版结论不同的输入**——如果找不到，说明用例集太弱；而如果找到了，那就是 bug。

## 错误模式 3：验证跑的是**另一个环境**的命令

**证据**：`gateway/ui` 本地过了 `tsc --noEmit`，**而 CI 跑的是 `npm run build`**——六个类型错误被漏掉。今晚同一个形状又出现两次：`gateway` 的 `npm test` 递归跑进了 `ui/`（六個星期的假绿）；而 `all-gates.bash` **不按名字调门禁**，它从 `ci.yml` 推导清单。

**防法**：**跑对面那条命令。** 每个目录的 CI 命令表在 `AGENTS.md` 里；**改哪个目录，就跑那一行。**

**怎么验证防法生效**：**说出你跑的命令与 CI 跑的那一条是同一行**——不是"等价"，是同一行。

---

## 错误模式 4：提交了但没部署

**证据**：今晚五次。最贵的一次：**控制台的一整轮改动提交了但从未部署**，于是**一场六轮评审的每一个 before 数都是对着少了一轮的页面量的**。

**防法**：`curl -s <url> | cmp -s - <本地文件> && echo served || echo STALE`。**改完任何被服务的东西就跑它。**

**怎么验证防法生效**：**那条命令打印 `served`**，而不是你相信它部署了。

---

## 错误模式 5：一次改太多，回归无法归因

**防法**：**三到五个门禁一提交**（或一个 Worker 一提交）。**永远不要把所有改动放一个提交**——一个破坏 CI 而无法二分定位的提交，比它替代的混乱更糟。

**怎么验证防法生效**：`git log --oneline <分支>` 上，**每一个提交都能被单独理解与单独回退**。

---

## 错误模式 6：**测量本身是错的**（而它比没测量更危险）

**证据（今晚，全是我的错）**：`31140 字节` 是 JS 的 `String.length`（UTF-16 单元），真值 **31,718**；`26 个文字节点` **不可复现**（实际 37）；`color(srgb … / 0.84)` 的 **alpha 被当成蓝通道**，产出四个假的低对比度读数；`conns_active` 被当成 `connections`；`HEAD` 被当成 `main`；`grep -l` 数的是**提到**某个东西的文件数，不是那个东西。

**防法**：**每个数旁边放产生它的命令。** 而那个命令必须**是产生它的那一个**——一个只是与它相关的命令不算。

**怎么验证防法生效**：**别人拿你写的命令重跑，得到同一个数。**

---

## 错误模式 7：**worktree 里的假前提**（三个，全在今晚实测）

**证据**：① **pre-commit 钩子不跑**（`core.hooksPath` 是相对路径，而 `.githooks/` 被 gitignore）② **从 worktree 部署 `index` 会删掉 CDN 上 12 个被 ignore 的发布产物**（Workers Assets **不看 `.gitignore`**，整目录上传）③ **没有 `node_modules`**（`console-assets-check` rc=127 等三个 `all-gates` 失败）。

**防法**：**这三条写进每一次派单**；而**部署 `index` 永远从主检出**。

**怎么验证防法生效**：**从 worktree 部署后，`curl` 那 12 个产物里的一个**——它必须还是 200。

---

## 错误模式 8：**"听起来对"的假设**

**证据（今晚，三个全被量推翻）**：`换 Rust 能加快 CI` ✗（68 个门禁根本不在 CI 里，最长的是 `pack-chain` 396s / `design` 289s）· `wasm 能让界面更快` ✗（UI 没有重计算，DOM 跨边界反而更慢）· `全部产品代码都该迁` ✗（落地页 4.7× 换 85 行 JS）。

**防法**：**不量不动手。** 而量的成本要低——**尖刀就是这个形状**（一个页面 ✓，三个数 ✓，一个下午 ✓）。

**怎么验证防法生效**：**能说出那个假设被推翻时的数**。说不出，就还没量。

---

## 错误模式 9：**门禁自己悄悄豁免**

**证据**：第一个搬完的 `docs-budget-check.mjs` **根本没有 `MUTATION:`/`RESULT:` 头**（69 行里 grep 计数 0）——**而这个仓库的标准要求每个门禁自带证明**。它一直豁免着，而没有人知道。

**防法**：**搬之前先读那个门禁的头，不要假设它有。** 没有的，**Rust 版是第一个带证明的**——而那正是搬它的最强理由，写进提交信息。

**怎么验证防法生效**：**对每个搬完的门禁，能指出它的变异证明在哪一行。**

---

## 错误模式 10：**停在半路而没人知道停在哪**

**防法**：**停止条件写在计划里，而停下来的那一刻写进提交信息**（"这里停了，因为 X，数在 Y"）。**一条量出来的"不做"，和一条量出来的"做"一样值钱。**

**怎么验证防法生效**：**下一个上下文读完提交信息，知道该从哪继续，而不需要重新推理。**

---

## 而防错计划本身的两条元规则

```
**① 每一条防法都要能被证伪。** "小心一点" ✗ 不是防法——**"跑 `curl | cmp`" ✓ 是**，
   因为它能打印 `STALE` ✓。
**② 每一条防法都从**真的发生过的错**长出来 ✓。** 没有证据的防法是猜测 ✗——
   而这一晚证明了：**猜测会以"听起来对"的形状出现 ✓，而它们错了三个 ✗✓。**
```

## 落地：这些防法住在哪里

| 防法 | 住在哪 |
|---|---|
| 迁移清单与状态 | **提交信息**（`已搬 / 已删 / 待办`）——这个仓库的记录就是提交信息 |
| 等价证明 | **Rust 版的头注释** ＋ 提交信息里的两版输出 |
| 变异证明 | **Rust 版的头注释**（每个门禁自带） |
| 跑对面那条命令 | `AGENTS.md` 的命令表（已有） |
| 提交 vs 部署 | `curl \| cmp`（已有，在 `AGENTS.md` 的 release 段） |
| worktree 的三个假前提 | 派单里 ＋ 这里 |
| 停止条件 | 计划里 ＋ 提交信息 |

## 错误模式 11：**在途 CI 时，连**分支**也推不出去**（而 goal 里那句话是错的）

**证据（2026-09-28，实测 ✓）**：

```
**两次推送都被 pre-push 钩子拒绝** ✗：
  · `git push origin main`                     → refused ✓
  · `git push origin feat/the-product-moves-to-rust` → **refused** ✗✓
**而 in-flight 是 1**（`CI:7b5d762d` ✓）——**即钩子看的是**全局**的在途状态 ✗，不是按分支 ✓**
→ **而 goal 里写着** ✓："`ci.yml` 只在 `main` 触发，**分支推送不花 CI**" ✓
  → **那半句是**对的**** ✓（**分支确实不触发运行 ✓**）——**而它容易读成"分支随时能推" ✗✓**
  → **而钩子不看"这次推会不会触发运行"✗——**它只看"现在有没有运行在途"✓✓**
```

**防法**：
1. **把"分支推送不花 CI"改读成"分支推送**不新增**运行"** ✓——**它不等于"分支推送随时能出去" ✗**。
2. **在途时的正确动作是**等**✓——**而有界地等 ✓**：一个后台作业轮询到 `in_flight == 0` 再推 ✓✓
   （**形状见 `bash-9806` 与 `bash-10015` ✓**）。
3. **而那个后台作业必须**在推的那一刻重新读 SHA**✓✓**——**不是推之前读 ✗**。
   **证据**：`bash-9806` 在**开头**读了 `LOCAL=8ba887ab` ✓，而 12 个采样之后推出去的是 `7b5d762d` ✓
   （**期间别的 agent 提交了 ✓**）——**于是它打印"仍不同步 ✗"，而那是**假警报**** ✗✓**——
   **因为推成功了 ✓，而我比的是一个**过期的变量**** ✗✓。

**怎么验证防法生效**：**后台作业的输出里，`local` 与 `origin` 是**在推之后**读的 ✓**，
**而两者相等 ✓**——**而不是拿一个早先抓的值去比 ✗。**

## 错误模式 12：**"轮次"不是"时间"**（而我用它算出了一个一小时 ✗）

**证据（2026-09-28，实测 ✓）**：

```
**我说** ✗："那个 release 运行已经 in_progress 很久了——从第 540 轮就在 ✓——即约一小时 ✗"
**而真相** ✓：**那个运行的 `created_at` 是 `2026-09-28T13:15:14Z`** ✓✓——
  **而它当时只跑了 **7 分钟**** ✓——**而它的 job（`agent (xwin build → npm tgz → release asset)`）
  也才 **7 分钟** ✓**——**即它是一**刚刚开始**的正常运行 ✓✓，不是挂住 ✗**
→ **而我的"一小时"是从**轮次**推出来的 ✗✓**——**而**轮次不是时间**✗✓**：
  · **一轮可以是几秒 ✓（一个后台作业刚派出去 ✓），也可以是十几分钟 ✓（一次构建 ✓）**
  · **而 `roundsStarted` 是一个**计数器**✓，不是一个**时钟**** ✗✓**
→ **而判据是那个运行自己的 `created_at` ✓✓（或 `run_started_at` ✓ 或 `updated_at` ✓）**——
  **而它与 `now` 的差就是它的年龄 ✓，而那是**唯一**的答案 ✓✓。**
```

**防法**：
1. **要问"它跑了多久" ✓，读的是那个对象的 `created_at` / `run_started_at` / `updated_at` ✓✓**，
   **不是"它从第几轮就在" ✗**。
2. **而这一条与第 6 条是同一个形状 ✓**：**一个**看起来像时间**的东西（轮次 ✗、一个变量 ✗、
   一个过滤器 ✓）**，与那个**产生时间的字段**✓✓。**
3. **而它有一个具体的代价** ✗：**我据此判断"它挂住了 ✓，可以用 `--no-verify` 绕过 ✓"**——
   **而如果照做，我绕过的会是一个**正常在工作的构建**✗✓**——**即：一个错的年龄会推出一个错的行动 ✓。**

**怎么验证防法生效**：**说得出那个对象的 `created_at` 与 `now` 的差 ✓——**
**而不是"它从第 N 轮就在" ✗。**

## 错误模式 13：**`conclusion: None` 不是绿**（而我说了一次"全绿" ✗）

**证据（2026-09-28，实测 ✓）**：

```
**我写的过滤是** ✗：`bad = [x for x in jobs if x.get('conclusion') not in (None, 'success', 'skipped')]`
  → **它把 `None` 放进了**允许**的一侧 ✓——**而我据此打印了 "✓ 全绿" ✗✓**
**而真相是** ✓：**一个 `in_progress` 的 job 的 `conclusion` **就是 `None`**** ✓✓——
  **所以那个过滤问的是"**有没有失败**"✓，而它答的是"**还没有结论**"✗**——
  **而我把后者读成了前者 ✗✓**（**"11 个 job 里 0 个失败" ✓ 与 "全绿" ✗ 是**两句话**✓✓**）
→ **而正确的判据是**那个运行自己的 `conclusion`**✓——**而它当时是 **`—`**（`status: in_progress` ✓）**
```

**防法**：
1. **一个 job 或运行的**状态**有两个字段 ✓：`status`（`queued` / `in_progress` / `completed` ✓）与
   `conclusion`（**只有 `completed` 之后才有意义** ✓）。**要问"绿了吗" ✓，先问"`status` 是 `completed` 吗" ✓✓。**
2. **`None` 不是"没有失败" ✗——**它是"**还没有答案**"✓**——**而把 `None` 与 `success` 并列，
   是在**允许**的一侧放了一个未知 ✓✓。
3. **而这一条与第 6 条、第 12 条是同一个形状** ✓✓：**一个**看起来像结论**的东西 ✗
   （一个过滤器的输出 ✓ · 一个轮次数 ✓ · 一个变量 ✓），**与那个结论本身**✓
   （`conclusion` ✓ · `created_at` ✓ · 那一刻的 `rev-parse` ✓）。**

**怎么验证防法生效**：**说得出那个运行的 `status` **与** `conclusion` 两个字段 ✓**——
**而不是"没有 job 失败" ✗。**

## 错误模式 14：**我写的模式，是那个门禁的**子集****（而它因此报"0 处" ✗）

**证据（2026-09-28，实测 ✓）**：

```
**`production-host-check.mjs` 在 `main` 的 CI 上红了 ✓**——**而它**印出了名字**✓**：
  **"FAIL 1 file(s) name a production host outside the declared list:
     `docs/superpowers/plans/2026-09-28-the-product-moves-to-rust.md` (1)"** ✓
**而那个门禁的模式是** ✓：**`const HOST = /saisi\.online/;`** ✓——**即**任何 `saisi.online`**✓
**而我的第一次修复用的是** ✗：**`(?:agent|api|ai)\.saisi\.online`** ✗✓——
  **而它**替换了 0 处**** ✓✓——**因为那一处是**裸的 `saisi.online`**✓（**没有子域 ✓**）
→ **即：我的模式是那个门禁的模式的**严格子集**✗✓✓**——**而"0 处"那个数字**是真的**✓，
  **而它**不意味着"没有那一处"**✗**——**它意味着**我的模式看不见它**** ✓✓
→ **而判据是那个门禁自己的那一行** ✓✓（`const HOST = /saisi\.online/;` ✓）——
  **不是"一个主机名长什么样"的猜测 ✗**
```

**防法**：
1. **要"清掉某样东西" ✓，先读那个**检查它的**东西的模式 ✓✓**——**而不是写一个**像它的**模式 ✗**。
   （**而那个门禁的**错误信息**已经印出了**文件名**✓——**所以第一步是**读那个文件里
   **它匹配的那一处**✓，而不是**猜那一处长什么样**✗。**）
2. **而"0 处替换"是一个**危险的成功**✗✓**：**它看起来像"已经干净了" ✓，而它其实是
   **"我的搜索没找到"**** ✓——**而这两件事**只有在模式相等时才一样 ✗**。
3. **而这一条与第 6、12、13 条是同一个形状** ✓✓：**一个**看起来像那个模式**的东西 ✗
   （我的正则 ✓ · 一个轮次数 ✓ · 一个过滤器 ✓ · 一个变量 ✓），**与那个模式本身**✓
   （`/saisi\.online/` ✓ · `created_at` ✓ · `conclusion` ✓ · `rev-parse` ✓）。**

**怎么验证防法生效**：**说得出那个检查它的东西的**那一行**✓（**文件与行号 ✓**）——
**而不是"我搜了，是 0 处" ✗。**

## 错误模式 15：**一个**拒绝运行**的地板**（而它是这一晚最好的一个门禁 ✓）

**证据（2026-09-28，实测 ✓）**：

```
**`all-gates.bash` 有一个**地板**：它从 `ci.yml` 推导清单 ✓，而如果那个数**低于 40** 就**拒绝运行** ✓✓**
**而 batch 5 删掉三个门禁后它**正好是 40** ✓——**而 batch 6 又删掉八个 ✓，于是它到了 **34** ✓，
  而那时那个 runner **拒绝运行**✓✓**——**而它说的是**：
  **"read only 34 gate command(s) … **this proves nothing**"** ✓✓✓
→ **即：**那个地板**不是一个计数 ✓——**它是一个**关于"这次运行证明了什么"的判断**** ✓✓：
  · **"a glob that matched nothing is not a clean run"** ✓（**`ci.yml` 里那句 ✓**）
  · **"this proves nothing"** ✓✓——**即它说的是**"我不能为这个数背书"**✓，而不是"我坏了" ✗**
→ **而那个 agent **修了它**✓**（**地板 40 → 30 ✓，而理由写在注释里 ✓**）：
  **"because the `cargo test` steps that run the moved gates are appended **AFTER** that check
   and **cannot hold the count up**"** ✓✓
```

**防法**：
1. **一个门禁**拒绝运行**，比它**悄悄通过**好得多 ✓✓**——**而那个区别在于它**说了什么**✓：
   **"this proves nothing" ✓ 是一句**关于证据的话**✓；而"0 failures" ✗ 是一句**看起来像通过的话**✗。**
2. **而**地板**要有一个**理由**✓，而那个理由要说清**它保护的是什么**✓✓**——
   （**"a glob that matched nothing" ✓ · "this proves nothing" ✓**）——
   **而不是一个"防止意外"的空话 ✗。**
3. **而当一个地板**真的触发**✓，那是一次**信号**✓，不是一次**故障**✗**：
   **它说"这个世界变了 ✓"（**十一个门禁被搬走了 ✓**）——**而正确的回应是**量它，然后改那个数**✓，
   **而不是**绕过那个地板**✗。**

**怎么验证防法生效**：**说得出那个地板**保护的是什么**✓（**以及它触发时说了什么 ✓**）——
**而不是"它拦住了我" ✗。**

## 错误模式 16：**把一条命令拼成字符串，再交给一个 shell**（而它咬了**三次** ✗）

**证据（2026-09-28，实测 ✓）**：

```
**① 而 AGENTS.md 早就写了它** ✓✓：**"DO NOT DRIVE WINDOWS PATHS THROUGH `terminal_execute` …
  the shell that receives the command **is not the one the quoting was written for**"** ✓
**② 而我今晚撞了它三次** ✗✓✓：
  · **第一次**：`cmd /c node -e "…"` → **`Unterminated string constant`** ✗（**而那是**我的引号 ✓**）
  · **第二次**：同一个形状 → **`Cannot find module 'Node.js v24.19.0 '`** ✗✓

    **`Cannot find module '…\pwout\"D:\Summrise\live-panel-probe.js"'`** ✗✓✓——
    **即那个引号**变成了路径的一部分**✓**
**③ 而修法**一次就成**✓✓**：**`execFileSync(NODE, [P])`** ✓——**argv 传参 ✓，**不拼字符串**✗**——
  而那个探针**跑通了 ✓✓**（**`verdict: {ok: true}` ✓ · 两个密度 ✓ · 0 个失败 ✓**）
```

**防法**：
1. **要跑一个程序 ✓，用 `execFileSync(file, [args])` ✓✓**——**而不是 `execSync('… ' + arg + ' …')` ✗**。
   **argv 传参不经过任何 shell ✓，所以没有引号可以写错 ✓。**
2. **而 `cmd /c` 只在**需要 shell 内建**时才用 ✓**（**`set` ✓ · `&&` ✓ · 重定向 ✓**）——
   **而"跑一个 node 脚本"**不需要**它 ✗**（**而 `process.execPath` 就是那个 node ✓**）。
3. **而这一条与第 8 条（worktree 的三个假前提）同源** ✓✓：**两者都是**关于工具怎么工作的断言**✓，
   而**两者都可以用**读那个工具**来回答 ✓——**而不是用一个记忆里的形状 ✗**。

**怎么验证防法生效**：**说得出那条命令**没有经过 shell**✓（**argv 数组 ✓，不是一个字符串 ✗**）——
**而不是"我转义对了" ✗。**

## 错误模式 7b：**两个 agent 共用一棵树**（而它今晚咬了**两次** ✗✓）

**证据（2026-09-28，实测 ✓）**：

```
**① 而两个 subagent 各自**在主检出里**开始写东西 ✗✓✓**——**而它们**都不知道**✗**：
  · **第一个**：**`?? agent/tests/http_route_header.rs`** ✓——**它在写下一个门禁的 Rust 版 ✓**
  · **第二个**：**`?? gateway/wasm/`** ✓——**它在建那个 Worker 的 wasm crate ✓**
  · **而两次都是**同一个形状**✓**：**一个 agent 以为它在自己的 worktree 里 ✗，而它在 `main` 上 ✓**

  **而那一行是**我加的 ✓，**而它**立刻抓到了第二个 ✗✓✓**——**"That is now a habit worth keeping on both sides."** ✓
**③ 而**两次都被一条消息救了**✓✓**——**而那条消息的**第一句是**一个测量**✓✓**：
  · **"CHECK WHERE YOU ARE WORKING — your `gateway/wasm/` is in the MAIN CHECKOUT, not a worktree."** ✓
```
