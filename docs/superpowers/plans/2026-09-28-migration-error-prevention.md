# 迁移防错计划 — 从**真的发生过的错**长出来

> 每一个错误模式都带**证据**（今晚实测，或 [secureyeoman 的 TS→Rust 复盘](https://raw.githubusercontent.com/MacCracken/secureyeoman/refs/heads/main/docs/development/migration-finds.md)）、**防法**、以及**怎么验证防法真的生效**。
> 判据是这一条：**防法本身也要能被证伪**——不然它只是又一句听起来对的话。

---

## 错误模式 1：迁移中**静默丢掉东西**（最贵的一个）

**证据**：secureyeoman 9 天迁了 944 条路由 / 54K 行，编译干净、核心域有真逻辑——**而中间件安全栈 16 层只搬了 5 层**（限流 / RBAC / 请求体限制 / IP 信誉 / 请求指纹 / 背压 / 所有权守卫 / 本地网络检查 / CORS 限制 / IPv6 规范化 / multipart 全缺）、**59 个端点没有 handler**（功能"silently broken"）、**Rust 侧零集成测试**。它的 `server.rs` 里甚至写着 `Stubs for Phase 7.1: …`——**acknowledged but never built**。

**防法**：
1. **迁移前先出清单**，逐项列出"现在有什么"。对门禁是 `ls scripts/test/` 的 68 个；对 Worker 是它的路由表；对 UI 是它的组件与导出。
2. **搬一个划掉一个**，而**"没搬"必须显式列出**——不是留白。
3. **每次提交的信息里带三行**：`已搬 / 已删 / 待办`。

**怎么验证防法生效**：迁移结束时，**清单上每一项的状态都是显式的**（搬了 / 删了 / 留着并写了为什么）。**只要有一项没有状态，防法就没生效。**

## 错误模式 2：等价没被证明就删旧的

**证据**：那份复盘的 TS 代码 **1,726 个文件一个都没删**——**而那是它还能被修的唯一原因**。反过来说：**删了就没法修**。

**防法**：**旧的在新版被证明等价之前不删。** 而"证明"不是"我看着像"——是：
- **同一份输入喂给两个版本，断言结论一致**（判决 **与消息文本**）
- **含失败用例与边界用例**（只有 happy path 的等价证明等于没证明）
- **再加一个"不该咬"的用例**（今晚那个：围栏内的 `###` 必须两版都过）

**怎么验证防法生效**：**能说出一个两版结论不同的输入**——如果找不到，说明用例集太弱；而如果找到了，那就是 bug。

---

## 错误模式 3：验证跑的是**另一个环境**的命令

**证据**：`gateway/ui` 本地过了 `tsc --noEmit`，**而 CI 跑的是 `npm run build`**——六个类型错误被漏掉。今晚同一个形状又出现两次：`gateway` 的 `npm test` 递归跑进了 `ui/`（六個星期的假绿）；而 `all-gates.bash` **不按名字调门禁**，它从 `ci.yml` 推导清单。

**防法**：**跑对面那条命令。** 每个目录的 CI 命令表在 `AGENTS.md` 里；**改哪个目录，就跑那一行。**

**怎么验证防法生效**：**说出你跑的命令与 CI 跑的那一条是同一行**——不是"等价"，是同一行。

---

## 错误模式 4：提交了但没部署

**证据**：今晚五次。最贵的一次：**控制台的一整轮改动提交了但从未部署**，于是**一场六轮评审的每一个 before 数都是对着少了一轮的页面量的**。

**防法**：`curl -s <url> | cmp -s - <本地文件> && echo served || echo STALE`。**改完任何被服务的东西就跑它。**

**怎么验证防法生效**：**那条命令打印 `served`**，而不是你相信它部署了。

---

## 错误模式 5：一次改太多，回归无法归因

**防法**：**三到五个门禁一提交**（或一个 Worker 一提交）。**永远不要把所有改动放一个提交**——一个破坏 CI 而无法二分定位的提交，比它替代的混乱更糟。

**怎么验证防法生效**：`git log --oneline <分支>` 上，**每一个提交都能被单独理解与单独回退**。

---

## 错误模式 6：**测量本身是错的**（而它比没测量更危险）

**证据（今晚，全是我的错）**：`31140 字节` 是 JS 的 `String.length`（UTF-16 单元），真值 **31,718**；`26 个文字节点` **不可复现**（实际 37）；`color(srgb … / 0.84)` 的 **alpha 被当成蓝通道**，产出四个假的低对比度读数；`conns_active` 被当成 `connections`；`HEAD` 被当成 `main`；`grep -l` 数的是**提到**某个东西的文件数，不是那个东西。

**防法**：**每个数旁边放产生它的命令。** 而那个命令必须**是产生它的那一个**——一个只是与它相关的命令不算。

**怎么验证防法生效**：**别人拿你写的命令重跑，得到同一个数。**

---

## 错误模式 7：**worktree 里的假前提**（三个，全在今晚实测）

**证据**：① **pre-commit 钩子不跑**（`core.hooksPath` 是相对路径，而 `.githooks/` 被 gitignore）② **从 worktree 部署 `index` 会删掉 CDN 上 12 个被 ignore 的发布产物**（Workers Assets **不看 `.gitignore`**，整目录上传）③ **没有 `node_modules`**（`console-assets-check` rc=127 等三个 `all-gates` 失败）。

**防法**：**这三条写进每一次派单**；而**部署 `index` 永远从主检出**。

**怎么验证防法生效**：**从 worktree 部署后，`curl` 那 12 个产物里的一个**——它必须还是 200。

---

## 错误模式 8：**"听起来对"的假设**

**证据（今晚，三个全被量推翻）**：`换 Rust 能加快 CI` ✗（68 个门禁根本不在 CI 里，最长的是 `pack-chain` 396s / `design` 289s）· `wasm 能让界面更快` ✗（UI 没有重计算，DOM 跨边界反而更慢）· `全部产品代码都该迁` ✗（落地页 4.7× 换 85 行 JS）。

**防法**：**不量不动手。** 而量的成本要低——**尖刀就是这个形状**（一个页面 ✓，三个数 ✓，一个下午 ✓）。

**怎么验证防法生效**：**能说出那个假设被推翻时的数**。说不出，就还没量。

---

## 错误模式 9：**门禁自己悄悄豁免**

**证据**：第一个搬完的 `docs-budget-check.mjs` **根本没有 `MUTATION:`/`RESULT:` 头**（69 行里 grep 计数 0）——**而这个仓库的标准要求每个门禁自带证明**。它一直豁免着，而没有人知道。

**防法**：**搬之前先读那个门禁的头，不要假设它有。** 没有的，**Rust 版是第一个带证明的**——而那正是搬它的最强理由，写进提交信息。

**怎么验证防法生效**：**对每个搬完的门禁，能指出它的变异证明在哪一行。**

---

## 错误模式 10：**停在半路而没人知道停在哪**

**防法**：**停止条件写在计划里，而停下来的那一刻写进提交信息**（"这里停了，因为 X，数在 Y"）。**一条量出来的"不做"，和一条量出来的"做"一样值钱。**

**怎么验证防法生效**：**下一个上下文读完提交信息，知道该从哪继续，而不需要重新推理。**

---

## 而防错计划本身的两条元规则

```
**① 每一条防法都要能被证伪。** "小心一点" ✗ 不是防法——**"跑 `curl | cmp`" ✓ 是**，
   因为它能打印 `STALE` ✓。
**② 每一条防法都从**真的发生过的错**长出来 ✓。** 没有证据的防法是猜测 ✗——
   而这一晚证明了：**猜测会以"听起来对"的形状出现 ✓，而它们错了三个 ✗✓。**
```

## 落地：这些防法住在哪里

| 防法 | 住在哪 |
|---|---|
| 迁移清单与状态 | **提交信息**（`已搬 / 已删 / 待办`）——这个仓库的记录就是提交信息 |
| 等价证明 | **Rust 版的头注释** ＋ 提交信息里的两版输出 |
| 变异证明 | **Rust 版的头注释**（每个门禁自带） |
| 跑对面那条命令 | `AGENTS.md` 的命令表（已有） |
| 提交 vs 部署 | `curl \| cmp`（已有，在 `AGENTS.md` 的 release 段） |
| worktree 的三个假前提 | 派单里 ＋ 这里 |
| 停止条件 | 计划里 ＋ 提交信息 |
