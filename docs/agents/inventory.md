## 3. MERGE — the same job in two places

### 3.1 `custom-prop-check.mjs` ⊂ `css-vars-check.mjs` (panel + console) `[measured]`
Both build a `defined` set of CSS custom properties and diff it against `var()` uses. Measured set sizes on this
checkout: **custom-prop 115, css-vars 114 — the difference is `--amber-bright`,** which occurs **only inside a comment**
(`agent/resources/panel-react/src/styles/layout.css:100`, `/* --warn-ink, not --amber-bright: … */`).

`css-vars-check.mjs:78-84` records this exact defect and fixes it ("COMMENTS ARE NOT DECLARATIONS"); `custom-prop-check.mjs:62-65`
still counts raw text. Consequence: the older gate would accept `color: var(--amber-bright)` as resolved — a silent false
pass — where the newer one fails it.

**Neither is disposable:** custom-prop also covers the **landing** (css-vars covers panel+console only,
`css-vars-check.mjs:26-29`), and css-vars adds the reverse direction (declared-but-unread, which found 21 tokens) plus
runtime `getPropertyValue` reads. **Merge:** strip comments in custom-prop, or hand it the landing slice alone and let
css-vars own panel+console.

### 3.2 `AGENTS.md` vs `agent/AGENTS.md` — the release procedure written twice `[measured]`
Diffed section by section: **Release 28 of 30 lines identical (93 %)**, Build 5/14 (35 %), Test 6/76 (7 %). The release
recipe (bump → build → cp exe → publish → one commit → tag via API → audit) is stated twice, near-verbatim.
**Merge:** keep one copy, point the other at it.

### 3.3 `DesktopShell`'s footer chip row, written twice in one file `[measured]`
`DesktopShell.tsx:520-527` (`showStatus`) and `:543-550` (`!showStatus`) render the same `BootChip`/`LoadChip`/`MonitorChip`/
`WaitingChip` with the same props — byte-identical apart from indentation. The two `className="desktop-status-msg"` spans
(`:512`, `:538`) are the same status line twice. **Merge:** hoist the row; let the boolean choose the wrapper only.

### 3.4 `TerminalWorkspace`'s two density branches `[measured]`
Desktop `:225-279` and panel `:280-381`: the `PathView`/`TrajectoryView`/`TerminalPane` mounts are copied
character-for-character (`:235-277` vs `:307-346`); the desktop branch adds only the container class and
`controlledView`. ~40 duplicated lines, two places to forget a prop — and the file's own comment at `:132-134` names
this exact trap ("a per-density copy is how the two drifted before (R131)"). **Merge:** one body, a density-aware
wrapper.

### 3.5 `useSessions.ts`'s session-row mapper, twice in one file `[measured]`
`:228` and `:329` are byte-identical after whitespace-trim (verified with `diff`) — the device session-row → `Session`
mapper, once in the event-driven tick and once in the 30-second sweep. `last_exit_code` and `idle_ms` each appear 5× in
that file. **Merge:** one function.

### 3.6 `PAGE_LABELS` vs `PAGE_TITLES` `[measured]`
`Shell.tsx:17-25` and `DesktopShell.tsx:109-116` carry the same six strings. The same file shows the fix already applied
to the icon map: `DesktopShell.tsx:32` **imports** `PAGE_ICONS`. **Merge:** import `PAGE_LABELS`. **Do not delete
`PAGE_LABELS`** — it is a test-only seam, which this repo counts as use (`scripts/test/exports-check.mjs:25`).

### 3.7 The update verdict is computed twice, and the two can disagree `[measured]`
The **same fact** ("is this device behind?") is derived in two places from two relays:
`agent/src/plugins/update/tools.rs:280-315` answers `GET /api/update` with `{current, latest, update_available}` — the
panel's `UpdateCard.tsx:143` renders that verbatim, pin-aware. The console does not read `/api/update` at all: it
computes `outdated = d.lastVersion !== install.version` (`DevicesPanel.tsx:349`), where `install.version` comes from
`/api/devices/install-cmd` → the deployment's CDN host plus `/api/version` (`devices.ts:663`; the literal is a declared location in `scripts/test/production-host-check.mjs`).

Both ultimately read the same published `version.json`, but the comparisons are different code: the device's uses
`newer()` plus the rollback pin, the console's is a string `!==` over a KV value written **at most hourly**
(`store/devices.ts:149`). So a pinned or just-updated device can show "current" in the panel and "update available" in
the console — and the panel already knows the better answer. **Merge:** have the console ask the device (it already
proxies to it) or have the gateway expose the device's own verdict, rather than re-deriving it from a lagging copy.

### 3.8 The crash verdict: the gateway forwards one value, the console tests it inline `[measured]`
`last_boot_kind` is a **five-value union** on the device, and the panel parses all five
(`useAgentVitals.ts:35-64` → `BootChip` + `lib/bootNotice.ts` rules, plus `/api/boots` for 24 h of history). The
gateway forwards **only `crashed`** (`gateway/src/mcp.ts:100-107`), and the console then matches the literal inline:
`st?.last_boot_kind === "crashed"` (`DevicesPanel.tsx:362-363`). The two agree on a crash and the console is blind to
`clean-exit` / `replaced` / `machine-restart` **by design** — but the design is encoded in a string comparison inside a
component, which is the shape this repo has already fixed twice (rounds 96-100). **Merge:** one parsed union on the
relayed payload, and let the console decide what it shows.

### 3.9 Four renderers over one array: already merged, keep it that way `[measured]`
Recorded here because it is the thing a future prune would get wrong: the four command views share one poll and two
groupers. The only genuine duplication in that area is a **fetch** (§5.2).

   (`UpdateCard.tsx:205`).

13. **Should the console's version badge carry the device's own verdict** (§3.7), or is "what the CDN publishes vs what
    the KV last saw" deliberately a different question?
14. **`build-installer.sh`: script or comment?** (§4.8)
